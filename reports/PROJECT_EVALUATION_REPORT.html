Abstract

Autonomous software development and AI-assisted program repair often suffer from a severe correctness gap: code generators cannot reliably judge the functional or security implications of their own outputs. On standard benchmarks, automated agents frequently exploit weak unit tests via specification gaming or reward hacking—passing narrow happy-path assertions while introducing regressions, incomplete fixes, or severe runtime vulnerabilities.

This report documents the design, practical implementation, and experimental evaluation of the Autonomous Code Validator (ACV). ACV replaces model self-assessment with an executable, multi-oracle verification engine. Candidate patches are executed in an isolated Linux kernel sandbox governed by resource.setrlimit() and evaluated across four deterministic gates: static AST rule checks, dynamic exploit Proof-of-Concept invalidation, regression test execution, and protected test shield verification. Evaluated across 7 real-world production open-source repositories (374 files, ~119,610 lines of code) across 20 live scenarios, ACV achieved 100% verdict accuracy with zero false accepts and zero false rejects.

1. Introduction & Problem Definition

Large Language Models (LLMs) and autonomous coding agents are increasingly utilized for automated software bug repair. However, recent empirical audits (e.g., SWE-bench Verified mutation studies) reveal that up to 77% of benchmark unit tests have blind spots. Agents capitalize on these unasserted logic paths by generating half-fixes, silencing exceptions, or hardcoding return values that pass test suites without resolving the root vulnerability.

The goal of this project is to develop an autonomous, deterministic verification system that:

  • Executes candidate patches against real-world vulnerability exploit triggers (Proof-of-Concept scripts).
  • Guarantees behavioral preservation by running full native regression suites (pytest).
  • Enforces operating-system-level process containment to protect host infrastructure against runaway loops or malicious subshells.
  • Generates reviewable Git hardening branches and Pull Requests without requiring human test synthesis.

2. System Architecture & Methodology

ACV operates via an unbypassable four-stage pipeline:

  • Stage 1: Static AST Security Oracle (acv-rules): A line-constrained Abstract Syntax Tree visitor inspects patch diffs for dangerous constructs (e.g., subprocess.Popen(..., shell=True), unsafe deserialization loaders, and unconstrained regular expressions).
  • Stage 2: Dynamic Exploit Invalidation Oracle: The candidate patch is applied to a clean clone of the repository, and the vulnerability's Proof-of-Concept script is executed. The patch is accepted only if the exploit is neutralized (exit code 1 or safe controlled exception).
  • Stage 3: Behavioral Regression Oracle: The project's existing pytest test suite is executed within the sandbox. The patch must pass all unit tests (exit code 0) to ensure zero functional regressions.
  • Stage 4: Protected Test Shield: ACV detects and blocks any patch that alters existing test oracles or disabled verification scripts, completely preventing specification gaming.
  • Operating System Containment: Subprocesses execute under Linux resource.setrlimit() capping RAM at 768 MB, CPU time at 30–60 seconds, and max file output at 16 MB. All child processes run in dedicated process sessions (os.setsid) terminated via os.killpg(SIGKILL) upon timeout.

4.2 Static Rule Qualification: acv-rules vs Bandit

We benchmarked our AST engine against the standard Python security linter bandit across 11 vulnerability tasks representing 10 CWE families:

Analyzer TP FP FN TN Precision Recall F1 Score Latency
acv-rules (Our Engine) 28 1 5 21 96.6% 84.8% 90.3% 62 ms
bandit (Baseline SAST) 17 3 16 19 85.0% 51.5% 64.2% 10,279 ms

acv-rules achieved a +26.1% higher F1 score than Bandit while running 165 times faster (62 ms vs 10,279 ms). Bandit exhibited a 48.5% false-negative rate on subtle injection variants.

4.3 Negative Control Validation (Pallets Click)

To prove zero false alarms on clean production software, Pallets Click 8.1.7 was evaluated as a negative control:

  • Clean Baseline: ACV cloned Click, verified zero vulnerabilities, ran all 56 functional unit tests, and returned an immediate ACCEPT (zero false alarms).
  • Backdoor Mutant: When an adversarial subshell injection (subprocess.Popen(..., shell=True)) was injected, ACV's AST checker immediately detected the rule violation and returned REJECT.

# 4. Synthesize reviewable Git hardening branch & Pull Request:
$ uv run acv repo-harden gitpython_cve_2022_24439 --diff my_fix.patch

When executed, acv repo-harden creates an isolated branch, verifies the patch against the Proof-of-Concept exploit and unit test suite, and outputs a formatted pull_request.md ready for review by software maintainers.

6. Conclusion & Future Scope

The Autonomous Code Validator successfully replaces untrusted LLM self-confidence with deterministic, executable verification. By combining line-constrained static AST rules with dynamic Proof-of-Concept execution inside a Linux-contained sandbox, the system achieved 100% verdict accuracy across 20 real-world scenarios without human intervention.

Future Scope:

  • Polyglot Expansion: Integrating Tree-sitter parsers to support Go, Rust, TypeScript, and C++ repositories.
  • Stateful CLI Benchmarks: Extending verification to operating system state diffs (e.g., Terminal-Bench environments).
  • Co-Evolutionary Verification: Automating continuous adversarial self-play between patch generators and verifier synthesizers.
