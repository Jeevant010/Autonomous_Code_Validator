Where to Put New Code & How to Run Verification

ACV is completely decoupled from mock files: it evaluates real codebases in contained workspaces.

1. Verify Candidate Code from CLI

Run deterministic gate against any task with your custom patch:

uv run acv repo-verify <task_id> --diff patch.diff
2. Generate PR / Merge Request

Automatically create a local hardening branch with full test evidence:

uv run acv repo-harden <task_id> --diff patch.diff
3. Intake New Repositories

Drop a new folder in repo_tasks/<new_task_id>/ with task.json, poc/exploit.py, and tests/test_functional.py.

Deterministic Oracle Contract & Safety Boundary

A candidate patch is accepted if and only if: (1) The security attack is blocked (exit 1 without crash), (2) The repository's own test suite passes (exit 0), (3) No new blocking AST checker findings are introduced, and (4) Protected test files and oracle definitions are never modified.
