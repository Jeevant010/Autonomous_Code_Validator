Verifying fixes against real open-source repositories

Each repository is cloned from GitHub at a release commit, its own test suite is run, and a trusted attack script is executed against it. Three patches are judged per repository: no patch, the real upstream fix, and a half fix that looks plausible. A correct system rejects the first and third, and accepts the second.

How to read a row

Attack is the script that proves the weakness is reachable. Fix is the patch under test. Tests is the repository's own suite, which must keep passing. A patch is accepted only when the attack is blocked, the tests pass, and the patch introduces no new static finding. Pre-existing findings in untouched code never block a patch.
